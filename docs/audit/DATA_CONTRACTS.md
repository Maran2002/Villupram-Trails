# MongoDB data contracts and index plan

This is a code-derived contract, not an enforced document schema. MongoDB remains schemaless and the project has no migration framework. `scripts/setup-indexes.mjs` indexes were applied to the configured Atlas database and verified on 2026-11-07. No separate staging database is available, so this does not establish staging/production acceptance.

| Collection | Critical stored fields / state | Relations and indexes defined | Retention state |
|---|---|---|---|
| `users` | `email`, `username`, bcrypt `password`, `role` (`user` / `admin`), admin `permissions`, `isVerified`, `sessionVersion`, timestamps | Email and username unique; role index. User ObjectId is referenced by reviews, reports, places, favorites, and audit entries. | No automatic expiry or account deletion schedule. |
| `places` | `name`, category, description, location, images, visiting hours, entry fee, amenities, status (`Pending`, `Approved`, `Rejected`, `Draft`), curated flags, rating/count, submitter, timestamps | Status/date, category/status, text name/description, submitter/date, visiting-days, status/updated-date. Reviews and favorites refer to place ObjectId. | No automatic expiry. Place deletion removes reviews and favorite references in application code; the multi-collection delete is not transactional and needs runtime failure-path verification. |
| `reviews` | place/user ObjectIds, author display fields, rating/content, visibility/moderation state, timestamps | Place/visibility/date, user/date, place/visibility. | No automatic expiry. |
| `reports` | report type, target ID (required for place/review/user reports), reason/description, reporter ID/contact fields, status (`pending`, `open`, `closed`), action fields, timestamps | Reporter/date, status/date, and date indexes; partial TTL on `updatedAt` for closed reports. | Closed reports expire 365 days after the status update that closed them; open reports do not expire through this index. |
| `support_tickets` | name, email, topic, message, status (`open`, `in-progress`, `closed`), timestamps | Status/date and email/date indexes; partial TTL on `updatedAt` for closed tickets. | Closed tickets expire 365 days after the status update that closed them; open tickets do not expire through this index. |
| `newsletter_subscribers` | normalized email, `subscribedAt`, status (`active`) | Unique email and subscription-date indexes. Public form stores addresses; admin list requires `newsletter.view`. No delivery or unsubscribe workflow is in scope. | No automatic expiry or self-service removal. Operator removes addresses manually when requested. |
| `settings` | singleton document `_id: 'site_config'`, site text/links and feature settings | Read by public settings APIs and written by admin settings API. No secondary index defined. | Singleton; no automatic expiry. |
| `visitor_logs` | New records: public path without query, referrer origin, coarse device/browser/OS, timestamp | Timestamp query index and 90-day TTL index. Private routes are excluded. No stable visitor identifier is stored in new records. | Records expire 90 days after `timestamp`; expiry is asynchronous. Older records may contain user-agent, screen-size, and client-supplied `ip` fields until TTL removes them. |
| `audit_logs` | actor ID/name/role, action, target, target ID, metadata, `createdAt` | Date, action, user, and target/target-ID indexes. TTL index expires entries after 365 days. | 365-day TTL index is present in the configured Atlas database. |
| `favorites` | user ObjectId, place ObjectId, `createdAt` | Unique user/place pair; user/date index. | No automatic expiry; deleting a place removes its favorite references in application code. |

## Deployment preflight

Before applying indexes to another environment or reapplying after schema changes, inspect the selected database for duplicate user emails/usernames, duplicate newsletter addresses, duplicate favorite pairs, and existing index-name/key conflicts. The configured Atlas database had zero duplicate groups for those unique keys and no conflicting secondary index definitions. The script requires `INDEX_SETUP_TARGET=local|staging|production|atlas`; `local` requires a loopback host, `atlas` requires a MongoDB Atlas hostname and `ALLOW_ATLAS_INDEX_SETUP=true`, and `production` additionally requires `ALLOW_PRODUCTION_INDEX_SETUP=true`. It is repeatable when existing data and index definitions are compatible, but does not repair duplicates or migrate documents. Partial TTL indexes require standard MongoDB collections (these collections are not configured as time-series collections).

The Atlas inventory was checked after application. Representative query plans used indexes for place browse, place reviews, report/support queues, newsletter listing, and visitor time ranges; the case-insensitive newsletter search used the subscription-date index while filtering email results. This is a functional index check on a small dataset, not a production-scale query benchmark. Do not infer that an index exists merely because it appears in the script.
